# PRD: Local LLM Chat 프론트엔드 UI

## 1. 목표
`frontend/docs/chat_ui_설계도.jpg` 디자인을 기준으로, 기존에 완성되어 있는 FastAPI + Ollama 백엔드와 연동되는 React 채팅 UI 화면을 구현한다. 현재 `frontend/`는 Vite + React 기본 템플릿 상태이며, 이를 실제 채팅 애플리케이션 화면으로 교체한다.

## 2. 대상 사용자 / 사용 시나리오
- **대상 사용자**: 로컬 PC에 Ollama를 설치해 두고, 여러 로컬 LLM 모델(gemma3, exaone 등)을 테스트/사용하려는 개발자 및 얼리어답터 1인 사용자(개인 로컬 환경 사용을 전제로 하며, 다중 사용자 동시 접속은 고려하지 않음).
- **사용 시나리오**:
  1. 사용자가 브라우저에서 앱을 열면 좌측에 모델 설정 패널, 우측에 채팅 화면이 보인다.
  2. 사용자는 좌측에서 사용할 모델을 선택하고, 시스템 프롬프트/Temperature/Top P/Num Predict 값을 조정한다.
  3. 사용자가 하단 입력창에 메시지를 입력하고 전송하면, 사용자 메시지가 채팅 목록에 추가되고 백엔드(`POST /chat`)에 요청이 전송된다.
  4. 응답 대기 중에는 "응답 생성 중..." 상태가 표시되고, 응답이 도착하면 AI 메시지로 채팅 목록에 추가된다.
  5. 사용자가 "대화 초기화" 버튼을 누르면 현재 화면의 대화 내역이 모두 지워진다.

## 3. 기능 요구사항

### 3.1 Must-have
- **레이아웃**
  - 좌측 사이드바 + 우측 메인 채팅 영역으로 구성된 2단 레이아웃 (설계도 기준).
- **좌측 사이드바 (모델 설정 패널)**
  - "모델" 드롭다운: 백엔드 `GET /models` 응답 목록으로 채움.
  - "시스템 프롬프트" 텍스트 영역: 입력값을 `/chat` 요청의 `system_prompt`로 사용, 기본값은 백엔드 기본값과 동일하게 표시.
  - "Temperature" 슬라이더: 0.0 ~ 2.0 범위(백엔드 스키마 기준), 현재 값 표시.
  - "Top P" 슬라이더: 0.0 ~ 1.0 범위, 현재 값 표시.
  - "Num Predict" 숫자 입력: 1 ~ 2048 범위.
- **우측 메인 영역 - 헤더**
  - 타이틀("Local LLM Chat")과 서브타이틀("React + FastAPI + Ollama 기반 로컬 AI 채팅 앱") 표시.
  - "대화 초기화" 버튼: 클릭 시 현재 채팅 메시지 목록을 초기 상태로 비움.
- **우측 메인 영역 - 메시지 목록**
  - 사용자 메시지와 AI 응답 메시지를 시각적으로 구분되는 말풍선으로 표시(설계도 기준 사용자 메시지는 우측 정렬/파란 배경 톤).
  - 메시지가 많아질 경우 세로 스크롤 가능.
- **우측 메인 영역 - 입력창**
  - 텍스트 입력창 + 전송 버튼.
  - 전송 시 사이드바에서 설정한 모델/시스템 프롬프트/temperature/top_p/num_predict 값을 함께 `POST /chat`에 전달.
  - 응답 대기 중에는 입력창/전송 버튼을 비활성화하고 "응답 생성 중..." 표시.
  - 응답 도착 시 AI 메시지 추가, 에러 발생 시 사용자에게 에러 상태를 화면에 표시.
- **API 연동**
  - `GET /models`(axios) 로 모델 목록 조회.
  - `POST /chat`(axios) 으로 메시지 전송 및 응답 수신 (스키마: `backend/schema.py`의 `ChatRequest`/`ChatResponse` 그대로 사용).

## 4. 비기능 요구사항
- **반응형**: 데스크톱을 기준 화면으로 하되, 모바일 폭에서도 레이아웃이 깨지지 않도록 대응(좁은 화면에서는 사이드바가 상단/토글 형태로 전환되는 등 최소한의 대응). 가로 스크롤이 발생하지 않아야 함.
- **성능**: 메시지 전송 및 모델 목록 조회 시 로딩 상태를 명확히 표시하여 사용자가 대기 상태를 인지할 수 있어야 함. 불필요한 리렌더링을 피한다.
- **접근성**: 입력창/버튼에 적절한 label 및 aria 속성 적용, 키보드만으로 메시지 전송(Enter) 가능해야 함, 색 대비가 충분해야 함.
- **에러 처리**: 백엔드 요청 실패(네트워크 오류, 5xx 등) 시 화면 크래시 없이 에러 메시지를 사용자에게 노출.
- **코드 품질**: 기존 프로젝트의 React + Vite 구조를 유지하며, 컴포넌트 단위로 분리하여 유지보수 가능하게 작성.

## 5. 프론트엔드 폴더 구조 (제안)
기존 Vite + React 템플릿 구조를 확장하여 아래와 같이 구성한다(세부 파일 단위는 이후 `task_plan.md`에서 확정).

frontend/

│   │   └── chatApi.js           # axios 인스턴스 + GET /models, POST /chat 호출 함수

## 6. 범위 제외 사항
- 백엔드(`backend/`) 코드, API 엔드포인트, 요청/응답 스키마 변경 요구 없음. `/chat`, `/models` 스펙은 있는 그대로 사용한다.
- `/frontend` 이하 실제 경로 파일 외의 파일(백엔드, 루트 설정 파일 등) 수정 금지.
- 로그인/인증, 다중 사용자 세션 관리, 대화 내역 서버 측(DB) 영구 저장 기능은 범위에서 제외(백엔드에 해당 기능 없음).
- 스트리밍(SSE/WebSocket) 응답 처리는 범위 제외(백엔드 `/chat`이 동기 응답만 지원).
